# 01 - Redis 是什么与为什么需要缓存

---

## 1. 从一个慢接口说起

用户打开做题页，浏览器请求：

```
GET /api/question/get/vo?id=2
```

当前后端逻辑（简化）：

```
1. MySQL：SELECT * FROM question WHERE id = 2
2. MySQL：SELECT * FROM user WHERE id = 创建者
3. 组装 JSON 返回
```

同一道题，1000 个用户做练习 = **至少 2000 次数据库查询**。  
题目内容含 LaTeX 题干、选项 JSON、解析，单行不小，数据库压力大、响应变慢。

**核心矛盾**：题目数据**读多写少**（管理员偶尔改题，用户疯狂读题）。

---

## 2. Redis 是什么

**Redis**（Remote Dictionary Server）是一个把数据放在**内存**里的数据库。

可以把它想成：

```
Java 里的 ConcurrentHashMap
  但是：在独立进程里、可跨多台服务器共享、带过期时间、重启可持久化
```

特点：


| 特点      | 说明                                 |
| ------- | ---------------------------------- |
| 快       | 内存读写，微秒～毫秒级                        |
| 简单数据结构  | String、Hash、List、Set、ZSet、BitMap 等 |
| 过期时间    | 适合缓存「过一段时间就过时」的数据                  |
| 单线程执行命令 | 命令原子，但一个热 key 可能打满 CPU             |


**不是用来替代 MySQL 的**。MySQL 仍是「权威数据源」；Redis 是**加速读**的辅助层。

---

## 3. 什么是「缓存」

**缓存**：把经常访问、变化不频繁的数据，复制一份放到更快的介质（Redis 内存），下次先读副本。

```
没有缓存：
  请求 → MySQL → 响应        （每次都慢）

有缓存：
  请求 → Redis 有？→ 有 → 响应   （快）
              ↓ 没有
            MySQL → 写入 Redis → 响应
```

类比：图书馆（MySQL）书很多但远；你桌边（Redis）放几本常看的复习资料。

---

## 4. 本项目哪些场景适合 Redis


| 场景            | 是否适合   | 原因                             |
| ------------- | ------ | ------------------------------ |
| 题目详情 `get/vo` | ✅ 非常适合 | 同一 id 被反复读                     |
| 用户签到日历        | ✅ 已在用  | BitSet 省空间，见 `UserServiceImpl` |
| 用户做题状态        | ⚠️ 一般  | 每人每题不同，key 多，读分散               |
| 题目列表分页        | ⚠️ 条件多 | 筛选组合爆炸，key 难设计                 |
| 写题目、改题目       | ❌ 不缓存写 | 直接写 MySQL，再删缓存                 |


本系列重点：**题目详情读缓存**。

---

## 5. MySQL 与 Redis 分工（本项目）

```
┌─────────────┐         ┌─────────────┐
│   MySQL     │  权威   │   Redis     │  加速
│  question   │ ◄────── │ question:   │
│  表         │  同步   │ detail:2    │
└─────────────┘         └─────────────┘
      ↑                        ↑
   增删改                   只读缓存
   永远正确                 可能短暂过期
```

记住两句话：

1. **读**：先 Redis，没有再 MySQL，并回填 Redis
2. **写**：先 MySQL，再删 Redis（不要只更新 Redis）

---

## 6. 为什么不用「把数据放 JVM 内存 Map」


| 方式     | 问题             |
| ------ | -------------- |
| 静态 Map | 多实例部署时各机器缓存不一致 |
| 无过期    | 题目改了，内存里还是旧的   |
| 重启丢失   | 要重新打满 MySQL    |


Redis 是**独立服务**，所有 Spring Boot 实例连同一个 Redis，缓存共享。

---

## 7. 本项目的 Redis 技术选型：Redisson

Java 连 Redis 常见两种方式：


| 客户端             | 说明                               |
| --------------- | -------------------------------- |
| Lettuce / Jedis | 偏底层，自己拼命令                        |
| **Redisson**    | 高级封装：`RBucket`、`RLock`、`RBitSet` |


项目 `pom.xml` 已依赖 Redisson，`RedissonConfig` 已配置；签到用的 `RBitSet` 就是 Redisson API。

题目缓存我们将用 `**RBucket<String>`** 存题目 JSON 字符串。
