# 05 - 缓存三大问题：穿透、击穿、雪崩

> 面试高频。本章用**题目详情**场景讲清定义、危害、对策。

---

## 1. 总览


| 问题     | 一句话                              | 本项目典型场景           |
| ------ | -------------------------------- | ----------------- |
| **穿透** | 查的数据**根本不存在**，缓存挡不住，每次都打 DB      | 恶意 `id=999999999` |
| **击穿** | **单个热 key** 过期瞬间，大量请求打 DB        | 模拟卷第 1 题过期那一刻     |
| **雪崩** | **大量 key 同时过期**或 Redis 挂了，DB 被打垮 | 批量导题后 30 分钟集体失效   |


三者区别：

```
穿透：key 从未存在 / 不该存在
击穿：key 存在且很热，过期那一刹那
雪崩：很多 key 或整个缓存层出问题
```

---

## 2. 缓存穿透（Cache Penetration）

### 2.1 过程

```
请求 id=999999999
  → Redis 没有
  → MySQL 也没有
  → 不缓存任何东西
  → 下一个请求再来一遍 …
```

攻击者用随机 id 刷接口，**缓存形同虚设**，DB 压力 = 无缓存。

### 2.2 本项目对策（按优先级）

**① 参数校验（已有）**

```java
ThrowUtils.throwIf(id <= 0, ErrorCode.PARAMS_ERROR);
```

**② 空值缓存（必做）**

DB 查不到时：

```java
bucket.set("#NULL#", 60, TimeUnit.SECONDS);
```

后续 60 秒内同样 id 直接返回「不存在」，不打 DB。

**③ 布隆过滤器（进阶，题量大时）**

启动时把所有题目 id 放进布隆过滤器；请求先过滤，肯定不存在的 id 直接拒绝。

面试说：「当前千级题目，空值缓存够用；百万题再加布隆。」

## 3. 缓存击穿（Cwache Breakdon）

### 3.1 过程

```
question:detail:2 是全校都在做的热题
  → 缓存 30 分钟到期
  → 同一秒 500 个请求同时 MISS
  → 500 个线程同时 SELECT MySQL id=2
```

只有一个热 key，但**并发极大**，叫击穿。

### 3.2 本项目对策

**① TTL + 随机抖动（Phase 1 必做）**

```java
ttl = 1800 + random(0, 300)
```

减轻「同一秒过期」概率，但不能完全避免热 key 过期。

**② 互斥锁（Phase 2 推荐）**

只有一个线程回源 DB，其他线程等待或重试读缓存：

```java
RLock lock = redissonClient.getLock("lock:question:detail:" + id);
if (lock.tryLock(3, 10, TimeUnit.SECONDS)) {
    try {
        // 双重检查：可能别的线程已回填
        String json = bucket.get();
        if (hit) return parse(json);
        Question q = getById(id);
        // set cache
    } finally {
        lock.unlock();
    }
}
```

**③ 逻辑过期（进阶）**

缓存值里带 `expireAt`，物理 key 不过期，异步线程刷新。适合超高 QPS。

**④ 热 key 永不过期 + 后台续期**

运营已知的热门卷，定时任务刷新 TTL。

## 4. 缓存雪崩（Cache Avalanche）

### 4.1 两种雪崩

**A. 过期时间集中**

管理员 14:00 导入 500 题，缓存 TTL 都是 1800s → 14:30 集体过期 → DB 瞬时 500 次查询。

**对策**：随机 TTL 抖动（见 ③ 课）。

**B. Redis 整体不可用**

Redis 宕机，所有请求打到 MySQL。

**对策**：

- Redis 高可用（主从、哨兵）— 运维层  
- 应用降级：`cache.enabled=false` 时直查 DB，并限流保护 DB  
- 本地 Caffeine 挡一层（第 ⑨ 课）

## 5. 三问题对照表（背这张就够）


|           | 穿透    | 击穿       | 雪崩                    |
| --------- | ----- | -------- | --------------------- |
| **原因**    | 数据不存在 | 热 key 过期 | 大量 key 同时失效 / Redis 挂 |
| **打谁**    | DB 每次 | DB 瞬时高峰  | DB 整体                 |
| **本项目方案** | 空值短缓存 | 互斥锁 + 抖动 | TTL 抖动 + 降级           |
| **实现章节**  | ⑥     | ⑧        | ③⑥                    |

## 6. 和业务结合的面试例子

> 我们做数学刷题，做题页 `GET /question/get/vo` 读多写少。穿透方面，对不存在的题目 id 缓存 `#NULL#` 60 秒；击穿方面，对 `question:detail:{id}` 在回源 DB 时加 Redisson 锁；雪崩方面，TTL 在 30 分钟基础上加 0～5 分钟随机。更新题目走先写 MySQL 再删缓存，保证不会长期脏读。
