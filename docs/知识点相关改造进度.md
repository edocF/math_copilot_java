| 删除        | `POST /delete`    | ❌     | Controller 已接，Service `removeKnowledgePointRecursively` 未实现 |


### Service 已实现逻辑

- `**addKnowledgePoint`**：`parentId=0` 作根节点；子节点继承父 `path` 拼 id
- `**validKnowledgePoint**`：名称非空、长度、sort ≥ 0
- `**validKnowledgePointForUpdate**`：名称/sort 校验；若改 `parentId` 则防自引用、防移到子孙下
- `**listKnowledgePointTree**`：O(n) 组树，按 `sort → id` 排序
- `**getQueryWrapper**`：`path` 前缀匹配（`likeRight`）供管理端查询

### 已知问题 / 刻意不做

1. **更新暂不支持改父节点（移动）**
  移动节点需级联更新子孙 `path/level`，复杂度高，当前 MVP **建议 update 只改 `name/sort`**。  
   若请求里仍传 `parentId` 且发生变化，`updateById` 不会同步 path，数据会不一致。
2. `**removeKnowledgePointRecursively` 未实现**
  调用 delete 接口会抛 `UnsupportedOperationException`。
3. `**list/tree` 分组**
  使用 `groupingBy(parentId)`，若库中存在 `parentId=null` 的根节点，不会出现在 `0L` 根列表中（种子数据均为 `0`）。
4. **缓存**
  目录树未接 Redis；建议前端 session 缓存 `/list/tree` 结果。

### 按知识点查题（核心）

**请求示例：**

```json
POST /api/questionKnowledgePoint/list/question/page/vo
{
  "knowledgePointId": 2,
  "includeChildren": true,
  "questionType": "single",
  "difficulty": 2,
  "current": 1,
  "pageSize": 10
}
```

**后端流程：**

1. 根据 `knowledgePointId` 查知识点，取 `path`
2. `includeChildren=true`（默认）：`path LIKE '/1/2/%'` 得到子树所有知识点 id
3. 在 `question_knowledge_point` 中查这些知识点关联的 `questionId`
4. 分页查 `question` 表，封装 `QuestionVO`

**前端分工（约定）：**


| 场景     | 调什么                                                  | 传什么                            |
| ------ | ---------------------------------------------------- | ------------------------------ |
| 左侧导航目录 | `GET /knowledgePoint/list/tree`                      | 无                              |
| 右侧题目列表 | `POST /questionKnowledgePoint/list/question/page/vo` | 只传 `knowledgePointId`（+ 分页/筛选） |


前端**不需要**自己用 `path` 查子树；`path` 仅后端内部使用。

## 五、path 字段设计说明（备忘）


| 用途   | 说明                               |
| ---- | -------------------------------- |
| 子树查询 | `path LIKE '/1/2/%'` 一次拿到节点及全部子孙 |
| 防环校验 | 移动节点时判断新父 path 是否包含 `/{当前id}/`   |
| 维护成本 | 移动节点需批量更新子孙 path（当前**不做**）       |


导航组树**只依赖 `parentId`**，不依赖 `path`。
