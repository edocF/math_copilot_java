# 数学刷题网站 —— 设计与技术亮点（面试项目）

> 在现有 Interview Copilot（Spring Boot 2.7 + MyBatis-Plus + MySQL/ES/Redis/COS）基础上，改造为**数学刷题平台**。AI Agent 微服务为后续规划，本文档暂不展开，仅预留接缝。

---

## 一、产品定位

面向数学练习的刷题平台。核心特色：**用"组卷 → 导出文档 → 纸笔作答 → 回填批改"的离线刷题闭环**，规避 web 端数学公式输入与主观题自动判题两大难题，同时沉淀错题本、掌握度等学习数据。

适配多学段（知识点树驱动，不写死中学/大学）。

---

## 三、核心刷题模式：组卷 → 导出 → 离线作答 → 回填批改

```
①组卷             ②导出              ③离线作答    ④回填批改              ⑤沉淀
按知识点/难度/   生成 PDF/docx    →  打印纸笔  →  逐题标 对/错/      →  错题入错题本
题型/随机/专项    含 LaTeX 公式                   部分对 + 自评分        更新掌握度/统计
组成一份练习      答案/解析另页                                         题目可再次组卷
```

**混合判题**：
- 客观题（单选/多选/判断/填空）→ web 上直接作答，系统**自动判**
- 主观题（解答/证明）→ 打印离线作答，回填时**自评对错**（判分逻辑后续可接 AI）

## 四、功能模块

### C 端（用户）
- 题目筛选浏览：按知识点 / 难度 / 题型 / 来源
- 刷题模式：顺序刷、随机刷、**专项练习**（选知识点）、**模拟试卷**（限时套题）
- 答题判题：客观题即时判；主观题离线作答 + 回填批改
- **错题本**：自动收集、重做、标记掌握（可接遗忘曲线复习）
- 收藏夹
- 学习统计：正确率、各知识点掌握度、刷题打卡日历

### B 端（管理员）
- 题目 / 知识点树 / 试卷 的增删改查
- **批量导入题目**（Excel）
- 数据看板（题量、错题热度榜）

## 五、数据模型

### 5.1 关系图

```
user ──< user_question_status >── question ──< question_knowledge_point >── knowledge_point(树)
 │              │                    │
 ├──< question_favorite >────────────┤
 ├──< wrong_question >───────────────┘  （后续）
 │
 └──< practice_record(组卷实例) >── question （后续）

question_bank(试卷/题集) ──< question_bank_question >── question
```

### 5.2 题目模型扩展（在现有 `question` 上）

| 新增/调整字段 | 用途 |
|---------------|------|
| `questionType` | 题型：single/multiple/judge/blank/subjective |
| `difficulty` | 难度 1–5 |
| `options` | 选择题选项（JSON） |
| `answer` | 标准答案（客观题=选项/数值；主观题=参考答案） |
| `analysis` | 解题解析/步骤（LaTeX，后续可由 AI 生成） |
| `source` | 题目来源 |
| `content` | 题干支持 **LaTeX**，前端 KaTeX 渲染 |

### 5.3 新增表

| 表 | 关键字段 | 说明 |
|----|----------|------|
| `knowledge_point` | id, parentId, name, path, sort | 知识点树，驱动专项练习与掌握度 |
| `question_knowledge_point` | questionId, knowledgePointId | 题目-知识点 多对多 |
| `user_question_status` | userId, questionId, status, result | 每用户每题一条；**不存作答**；status：`not_done`/`pending`/`done`；done 时 result：`correct`/`wrong` |
| `question_favorite` | userId, questionId | 收藏（硬删除） |
| `practice_record` | （后续） | 一次组卷/导出实例 |
| `wrong_question` | （后续） | 错题本；可在标错时从 `user_question_status` 同步 |

**`user_question_status` 校验**：`not_done`/`pending` 时 `result` 必须为 NULL；`done` 时 `result` 必须为 `correct` 或 `wrong`。

> 状态表、收藏表无 `isDelete`；收藏取消用物理删除。题目/知识点等仍用逻辑删除。

## 六、技术亮点（面试可讲的"做文章"点）

> 建议**挑 3~4 个讲深**，而非全部铺开。下方 ⭐ 越多越推荐主打。

### A. 本项目特有亮点

1. **组卷导出 PDF/Word + LaTeX 公式渲染** ⭐⭐⭐
   - 难点：公式在文档中正确渲染；大卷导出慢
   - 方案：LaTeX → KaTeX/MathJax 渲染 HTML → wkhtmltopdf/Playwright 转 PDF；docx 走 freemarker/poi-tl 模板
   - 进阶：**异步导出任务** + 进度查询 + 文件存 COS + 限流
2. **智能组卷算法** ⭐⭐
   - 按知识点配比 + 难度分布 + 题型数量约束抽题；避免 `ORDER BY RAND()`，用分桶/加权随机
3. **MySQL → ES 同步一致性** ⭐⭐⭐
   - 现状：每分钟定时增量同步
   - 演进：Canal 监听 binlog / MQ 异步双写；最终一致性方案对比
   - 进阶：IK 分词、高亮、按知识点/难度聚合

### B. 缓存与高并发

4. **Redis 缓存三大问题** ⭐⭐⭐（以题目详情热点读为场景）
   - 穿透（布隆过滤器/空值缓存）、击穿（互斥锁/逻辑过期）、雪崩（过期打散）、缓存一致性（延迟双删/Canal）
5. **排行榜 / 打卡（Redis ZSet + BitSet）** ⭐
   - 错题热度榜、刷题排行榜、签到日历

### C. 并发安全

6. **接口幂等 + 防重复提交** ⭐⭐
   - 场景：批改回填、组卷、签到；用 Redisson **分布式锁**（已引入）、Token 幂等、唯一约束
7. **接口限流** ⭐
   - 导出、ES 搜索；令牌桶/滑动窗口 + Redis（替代现有 pageSize 硬判断）

### D. 认证授权

8. **JWT 无状态认证升级** ⭐⭐
   - 现状已是亮点：**JKS + RSA 非对称签名**（讲非对称的意义）
   - 升级：access + refresh 双令牌续期；登出/封号 token **Redis 黑名单**；多端登录控制
   - 真正的 SSO 等接入 AI 微服务后，做"统一认证中心"更名正言顺
9. **RBAC 权限模型** ⭐
   - 角色写死 → 角色-权限表驱动，配合现有 `@AuthCheck` AOP

### E. 数据 / 工程化

10. **批量导入题目（EasyExcel）** ⭐⭐：流式读、分批入库、事务、错误行回执
11. **错题本遗忘曲线复习** ⭐⭐：艾宾浩斯 / SM-2 间隔重复算法安排复习
12. **深翻页 & 统计聚合性能** ⭐：游标分页；掌握度预聚合/定时汇总

### 推荐主打组合

> ① 组卷导出+公式渲染（独特性）+ ② ES 同步一致性 + ③ Redis 缓存三大问题 + ④ Redisson 幂等防重，认证用「RSA-JWT + Redis 黑名单」点缀。

## 八、改造落地顺序建议

1. **数据层**：扩展 question + knowledge_point / question_knowledge_point / user_question_status / question_favorite（已完成 DDL）；后续 practice_record / wrong_question

3. **核心闭环接口**：组卷 → 导出 → 回填批改 → 错题/统计
4. **技术亮点逐个落地**：导出异步化 → 缓存 → ES 同步 → 幂等限流 → 认证升级
